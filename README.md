# 固定块分配器（从 0 实现）

起始环境只有本说明、`samples/**` 与 `.gitignore`，没有实现代码：分配器（库 + 命令行入口）和一页原生 HTML/Canvas 的池视图都从零写。Python 3.13 标准库，不引第三方、不加构建、不联网。同一份脚本跑两遍，输出必须逐字节相同。

## 一、范围

做：读分配释放脚本；按固定单元与档位表申请、释放、扩池；空闲块分链、合并、按唯一规则复用；每条操作打一行记录，带这一步的占用、碎片与空闲块数；把最终布局打成文本；把池布局与占用/碎片曲线画成一页自包含网页；四个子命令；`unittest` 测试。

不做：不做紧凑打包与压缩；不做线程安全、并发与多池；不做跨进程共享、持久化、自动缩池；不做引用计数与垃圾回收；不支持 64 字节以外的对齐；不引第三方依赖、不加构建；网页只做人工查看、不参与逐行比对；不改动 `samples/**`。

## 二、口径与公式

- 单元 64 字节：第 `i` 个单元的字节区间是 `[64i, 64i+64)`，块是一段连续单元 `[start, start+units)`。
- 扩池 `grow k`：向池尾追加 `k × 64` 个单元（`k ≥ 1`，缺省 1）；新追加的部分先与池尾的相邻空闲块合并。
- 分级：请求 `n` 字节（`n ≥ 1`）先算 `u = ceil(n / 64)`，再取单元表 `(1, 2, 3, 4, 6, 8, 12, 16)` 里不小于 `u` 的最小项当档位，块容量 `cap = 64 × 档位`。`u > 16` 记 `status=too_big`，不改状态。
- 对齐：块起始地址 `start × 64` 必为 64 的倍数，块容量也是 64 的倍数；不提供更大的对齐。
- 取块：在容量不小于 `cap` 的空闲块里挑「容量最小」的一块，容量并列取「起始下标最小」的一块；命中块比 `cap` 大就按末尾切分，余下部分照常当空闲块归档。池里没有整块装得下就记 `status=no_space`，不自动扩池。
- 释放：块交回空闲表，并与左右相邻的空闲块合并（一次释放最多并三块），合并结果按容量归档。
- 空闲链：容量恰为某档位的空闲块进该档位链（`chain=1..8`），其余进零头链（`chain=rest`）；每条链按 (容量, 起始下标) 升序，同一块只出现在一条链上。
- 块号从 1 起自增，释放后不复用。
- 内部碎片 `W_i = cap_i - n_i`：逐块 `W_i ≤ 255` 字节；`n_i ≥ 65` 时 `2 × W_i < cap_i`（不到半档）；`n_i` 是 64 的整数倍时 `W_i = 0`。
- 每一步的统计六件套：`P` 池字节、`U` 存活块容量合计、`W = ΣW_i`、`L` 存活块数、`FB` 空闲块数、`FR = P - U` 空闲字节。
- 占用率 `occ = U / P`、利用率 `util = (U - W) / P`、碎片率 `frag = W / U`，分母为 0 时记 `0.000000`；`util ≤ occ ≤ 1`，样例每一步都有 `frag ≤ 1/2`。
- 不变量（每步之后都要成立，自检不过退出码 3、打一行 `invariant: …`）：块互不重叠且都在池内；空闲块互不重叠也不相邻（合并干净）；`P = U + FR`、`U = 64 × 存活单元数`、`W` 与存活块逐块重算一致；一个块号至多释放一次。

## 三、状态机与数据结构

状态：池单元数；存活表 `块号 → (起始下标, 单元数, 请求字节, 档位)`；空闲表 `起始下标 → 单元数`；8 条档位链加 1 条零头链；块号计数器；`ops / ok / no_space / too_big / freed` 计数。

三条转移：`grow` 追加并合并，永远成功；`alloc` 走成功、`too_big`、`no_space` 三个出口，只有成功改状态；`free` 成功，块号不存在或已释放是输入错误，出错整条脚本作废。分配只切尾、不搬移；释放必须并干净；链序不能乱。

## 四、输入输出与文件格式

本节文件一律 UTF-8、`\n` 换行、末行有换行。

### 4.1 脚本 `samples/scripts/<名>.txt`

`#` 开头的行与空行忽略，其余每行一个操作：

```
grow [k]      # k ≥ 1，缺省 1：追加 k × 64 个单元
alloc <n>     # n ≥ 1：申请 n 字节
free <id>     # 释放一个还活着的块号
```

参数只认十进制非负整数，不接受符号与小数点。`alloc 0`、`free` 不存在的块号、看不懂的操作都是输入错误：退出码 2、stderr 一行 `error: …`、不留半成品。

### 4.2 记录（`run` 的 stdout）

一行一条，`|` 分隔的 `键=值`，字段顺序固定；操作行在前，末尾一行 `END`。`n=` 是操作序号（从 1 起，注释与空行不算），`cls=` 是档位序号（从 1 数起），`cap=`/`added=` 是字节数，`start=`/`units=` 是单元下标与单元数；六件套顺序固定，`END` 是 `END|ops=|ok=|no_space=|too_big=|freed=|` 接六件套。下面五行摘自 `01_mixed`，原样可对：

```
GROW|n=1|times=2|added=8192|P=8192|U=0|W=0|L=0|FB=1|FR=8192
ALLOC|n=3|req=100|status=ok|cls=2|cap=128|id=2|start=1|P=8192|U=192|W=28|L=2|FB=1|FR=8000
ALLOC|n=16|req=1200|status=too_big|P=8192|U=3328|W=374|L=8|FB=1|FR=4864
FREE|n=10|id=3|units=3|P=8192|U=3136|W=482|L=7|FB=2|FR=5056
END|ops=29|ok=17|no_space=0|too_big=2|freed=8|P=12288|U=6080|W=478|L=9|FB=3|FR=6208
```

`status=ok` 的申请才有 `id` 与 `start`；`no_space` 只有 `cls` 与 `cap`（池满那行长这样：`ALLOC|n=26|req=1024|status=no_space|cls=8|cap=1024|P=20480|U=20480|W=0|L=20|FB=0|FR=0`）；`too_big` 两个都没有。

### 4.3 命令行

```
python3 blockhall.py run   <脚本>              # 逐行打记录到 stdout
python3 blockhall.py check <样例根目录>         # scripts/*.txt 与 expected/<同名>.txt 逐字节比
python3 blockhall.py dump  <脚本>              # 打最终布局，末行同 END
python3 blockhall.py draw  <脚本> <输出.html>   # 一页自包含 Canvas
```

`check` 全过打一行 `ok=<组数>`，有不符的每组打一行 `mismatch=<脚本名>` 并退出码 1。`dump` 先跑完整条脚本，再按起始下标升序打最终布局，每行一个片段，首尾相接盖满 `[0, P/64)`（下面两行摘自 `01_mixed` 的最终布局）：

```
MAP|start=22|units=2|kind=free|chain=2
MAP|start=24|units=12|kind=live|id=11
```

退出码：0 成功、1 有样例不符、2 用法或输入错误、3 不变量自检失败。

### 4.4 页面

`draw` 写一页单文件 HTML：原生 HTML + Canvas，样式与绘制脚本内联、不引外链、`file://` 双击即开。画三样：池布局（一个单元一格，存活块按档位着色并标块号，空闲块按档位链与零头链分色）、底部曲线（`occ`、`util`、`frag` 随操作序号变化）、底部一行汇总。页面上的数只许取自引擎记录，末尾汇总与同一脚本 `run` 的 `END` 行逐字段一致；版式与配色自定。

## 五、性能与验收口径

测试机 Windows + Python 3.13，单进程单线程，只用标准库。

1. 逐组核对：`python3 blockhall.py check samples` 打 `ok=6`，没有 `mismatch`；每条记录与 `samples/expected/<名>.txt` 逐字节相同（空格、行序、末行换行都要对）。
2. 规模：`06_scale`（两万条操作）单次 `run` ≤ 1.5 秒，峰值内存 ≤ 128 MiB（`tracemalloc` 扣基线）；隐藏验收放大到十万条时，单步摊销 ≤ 150 µs。
3. 确定性：同一脚本连跑两遍，再换 `PYTHONHASHSEED=0/1/2` 跑，输出逐字节相同；不读时钟、不用随机数，链序与容器遍历顺序不决定输出。
4. 不变量：每一步自检不重叠、空闲不相邻、`P = U + FR`；`dump` 的片段首尾相接、盖满全池。
5. 失败不留痕：`no_space`、`too_big` 的记录除自身外，六件套与上一条记录完全一致。
6. 错误路径：`free` 已释放或不存在的块号、`alloc 0`、`alloc abc`、`grow 0`、看不懂的操作，一律退出码 2、stderr 一行、不写输出文件。
7. 页面：`draw` 出的 HTML 无外链，末尾汇总与 `END` 行一致。
8. 测试：`unittest`；只读 `samples/**`，写只写 `var/` 与 `draw` 的输出路径；样例文件一个字节都不许改。

## 六、样例说明

`samples/scripts/<名>.txt` 与 `samples/expected/<名>.txt` 同名一一对应，共六组。

| 名 | 场景与关键数字 |
| --- | --- |
| `01_mixed` | 大小混合：八档各申请一块，穿插释放与切分；29 步 17 次成功、2 次超档；`alloc 150` 拿回刚空出来的 `start=3`，末尾 `P=12288 U=6080 L=9 FB=3` |
| `02_burst` | 批量申请后集中释放：扩 4 格后连申请 200 个 64 字节块，先放奇数号再放偶数号；空闲块数 100 → 1，放完时 `U=0 FB=1 FR=16384` |
| `03_samesize` | 同尺寸反复周转：三块 200 字节轮转 12 轮，地址按 `0/4/8` 循环，`FB` 只在 1 与 2 之间跳 |
| `04_growonly` | 长期只申请不释放：五轮各扩一格、每轮塞四个 1024，池满后连吃 3 次 `no_space`；再扩 2 格，前面失败的三个请求重试都成功 |
| `05_retry` | 失败与重试：池空先失败，扩池后同一个请求成功；两次超档不改状态；释放后拿回 `start=0`；池塞满一格块再放掉一半，`FR=1536` 却装不下 `alloc 1024`，扩池后成功 |
| `06_scale` | 规模样例：两万条操作（10173 次成功、9772 次释放、27 次 `no_space`），压时限与查确定性 |

`samples/notes.md` 是现场记录，只作背景，不作为口径。
